# Fred's POS 前端開發總指引 (Master Prompt)

> **版本**：1.1.0  
> **專案目標**：模型車專門店 (Fred's POS) 前端互動式 Mockup 系統  
> **展示對象**：業主 (Fred & Fay) 進行 UI/UX 審查與業務邏輯確認  
> **展示里程碑**：業主 Demo 審查（滾動更新，不以固定日期為硬性截止）  
> **設計風格**：暗色系現代科技感 (Dark Mode Modern Tech)  
> **核心亮點**：極速結帳 Autocomplete、手動改價、預購分批到貨與部分取貨沖銷、多地點庫存調撥、組合支付與找零。

---

## 1. 給實作 AI 的角色與任務定義

你是一位專精於 **React 18/19、TypeScript、Tailwind CSS、Zustand 與前端領域驅動設計 (DDD)** 的資深前端架構師。

你的任務是根據 `fe/prompts/` 資料夾下的規格文件，打造一套可獨立運行、高互動性、狀態持久化的 **Fred's POS 前端 Mockup 系統**。

### 核心原則：
1. **Mock 逼真度最高要求**：
   - 所有的 API 交互均使用前端 Service Adapter + `localStorage` 進行持久化儲存。
   - 頁面重新整理（Refresh）或在側邊欄切換畫面時，購物車、新增的商品、更新的庫存、結帳單據、預購單沖銷狀態**絕不可遺失**。
   - **持久化分工**（詳見 `01` 第 3.1 節）：業務資料走 Service → localStorage；購物車走 `zustand/persist`；UI 暫態（Modal 開合）不持久化。
   - 提供模擬非同步延遲（約 100~200ms）以表現真實網路狀態，並附帶載入骨架屏或 Spinner。
2. **極致暗色系科技感 UI**：
   - 底色以 Slate-900 / Zinc-900 為主，搭配高對比的文字、精緻邊框 (Zinc-800) 與狀態亮色 (Emerald 綠代表成功/現貨、Amber 橘黃代表預訂/警告、Cyan 青藍代表主要操作與強調)。
   - 數字採用等寬字體 (Monospace / `font-mono`)，符合專業收銀機與門市 POS 的清爽閱讀體驗。
3. **架構嚴謹性**：
   - 嚴格分離 UI 元件與業務邏輯，嚴禁撰寫超過 250 行的單一巨大檔案。
   - 遵循 `01-architecture-and-services.md` 所定義的介面層與 Service Adapter 模式。
4. **API 規格同步更新**：
   - **實作前端程式的同時，必須將用到的 API 更新到 `docs/` 資料夾裡的 `openapi.yaml`**。
   - 包含新增或調整的 API 端點、請求參數 (Request Payload)、回應格式 (Response Schema) 與業務錯誤碼，確保前端實作與 OpenAPI 規格契約始終保持一致。
5. **編譯產物版本控管 (Track dist/ in Git)**：
   - 若執行 `npm run build`，**不需要也不得將 `dist/` 資料夾清除**；專案需要將編譯產出的 `dist/` 一起提交並納入版本管理中。
6. **規格與 Prompts 同步更新 (Continuous Prompts Sync)**：
   - **實作或調整前端功能、畫面佈局與業務動線時，必須同步更新 `prompts/` 規格文件**，確保後續開發與規格說明永遠對齊最新程式碼實作。

## 4. 交付與驗收標準 (Acceptance Criteria)

1. **可執行性**：
   - 專案能以 `npm run dev` 零報錯啟動，無 TypeScript 型別錯誤或 Lint 警告。
2. **完整操作閉環 (Happy Path)**：
   - **情境 A**：現場散客購買現貨，搜尋商品 -> 加入清單 -> 手動改價折 100 元 -> 現金支付 2000 元 -> 系統找零並完成出單。
   - **情境 B**：預購客戶取貨，輸入電話帶入預購單 -> 該單預訂 2 台本次到貨 1 台 -> 勾選領取 1 台帶入結帳清單 -> 刷卡結帳 -> 結帳後原預購單狀態更新為「部分已結」，庫存扣減。
   - **情境 C**：商品庫存調撥，將倉庫 3 台調至門市，即時反應在結帳櫃檯現貨數量。
3. **資料重置功能**：
   - 在介面角落提供一個小巧的「重置示範假資料」按鈕，方便業主在反覆測試後一鍵還原乾淨的展示資料庫。
4. **API 規格同步 (OpenAPI Sync)**：
   - 實作前端程式與功能時，所有用到的 API 均同步更新至 `docs/` 資料夾裡的 `openapi.yaml`，確保 HTTP API 契約與前端實作完全對齊。
5. **版本管理與建置產物 (Build Artifacts Tracking)**：
   - 若執行 `npm run build`，編譯產出的 `dist/` 資料夾不得刪除，須一同納入 Git 版本管理。
